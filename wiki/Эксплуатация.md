# Эксплуатация

## Синхронизация

Полная синхронизация — около 15 запросов к REG.RU (лимит аккаунта 1200/час, локальный предохранитель 1100):

1. `service/get_list` — услуги;
2. `domain/get_nss` — NS одним списком;
3. `service/get_info` — автопродление;
4. `service/get_details` — данные хостингов (только для услуг, где ещё не спрашивали);
5. `zone/get_resource_records` — DNS-зоны пакетами по 10 доменов.

Этапы независимы: ошибка одного даёт статус `partial`, остальные данные сохраняются.

Команды:

```bash
php backend/bin/regru sync --scope=all
php backend/bin/regru sync --scope=services   # быстрее
php backend/bin/regru sync --scope=dns
php backend/bin/regru sync --json             # машинный вывод
```

Cron-пример — в [[Установка]].

## Резервные копии

```bash
php backend/bin/regru backup
```

Создаёт `var/backups/regru-YYYYmmdd-HHMMSS.sqlite` через `VACUUM INTO` (консистентный снимок WAL) и оставляет 14 последних копий. Храните копии вне веб-корня. Ключ `APP_KEY` в бэкап не входит — без него пароли не расшифровать, поэтому `.env` бэкапьте отдельно.

## Обновление

```powershell
pwsh -NoProfile -File tools/deploy.ps1
```

Перед распаковкой предыдущий релиз архивируется в `/root/regru-backup/`. Миграции применяются автоматически. Откат — распаковать архив и восстановить `var/` при необходимости.

## Диагностика

```bash
php backend/bin/regru doctor --online   # окружение + доступ к API
php backend/bin/regru routes            # маршруты
tail -100 var/log/app.log               # JSON-лог, без секретов
```

В журнале каждая строка содержит `request_id`; он же есть в ответе API и в заголовке `X-Request-Id`.

## Мониторинг

- `GET /api/v1/health` — публичный, отдаёт статус и версию (удобно для uptime-проверки).
- `GET /api/v1/sync` — когда была последняя успешная синхронизация, не устарели ли данные.
- Страница «Журнал» — входы, изменения, раскрытия паролей.
- Ошибки REG.RU API видны в истории синхронизации и в логе (`REG.RU business error`, `api_code`).

## Что делать при сбоях

Частые коды REG.RU (`ACCESS_DENIED_FROM_IP`, `PARAMETER_MISSING`, `DOMAIN_IS_NOT_USE_REGRU_NSS`, `INSUFFICIENT_FUNDS`) и их лечение — в `docs/TROUBLESHOOTING.md` репозитория.

## Ограничения API REG.RU

- Пароли панелей отдаются не для всех типов услуг — недоступные сохраняются вручную в «Доступах».
- DNS через API управляется только для зон на `ns1.reg.ru`/`ns2.reg.ru`.
- Некоторые команды недоступны обычному аккаунту (только партнёрам) — видно в каталоге.
